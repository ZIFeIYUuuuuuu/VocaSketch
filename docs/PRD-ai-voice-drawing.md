# AI 语音绘图工具 PRD

## 1. 产品概述

本产品是一款面向比赛 demo 的 AI 语音绘图网页工具。用户无需鼠标键盘，主要通过中文语音描述创作意图，AI 将自然语言拆解为可执行绘图操作，并在数位绘画工作台中完成半身二次元头像创作。

MVP 聚焦“二次元半身头像 + 水彩上色 + 素描线稿”主题。产品不以端到端 AI 生图作为核心能力，而是通过语音理解、绘图操作规划、组件化头像结构、语义图层和绘画过程控制，生成可编辑、可分层、可回放的绘图工程。

## 2. 比赛定位

所选题目：题目二，AI 语音绘图工具。

核心答题方向：

- 用户不能依赖鼠标键盘完成核心创作流程。
- 用户通过语音完成创建、确认、修改、暂停、继续、撤销、回放等操作。
- 系统强调语音指令理解准确性、容错性、响应延迟和复杂指令拆解能力。
- 作品最终不是单张 AI 生成图片，而是由对象、图层、笔刷路径和操作历史组成的绘图工程。

## 3. 产品目标

### 3.1 MVP 目标

- 用户用一句中文语音创建二次元半身头像。
- AI 复述理解结果，用户确认后开始绘制。
- 系统自动完成草图、线稿、铺色、水彩渲染和细节阶段。
- 用户可通过连续语音对话修改局部内容。
- 用户可暂停、继续、撤销、重做和轻量回放绘画过程。
- 前端展示图层面板和绘画状态，证明作品不是端到端生图。

### 3.2 非目标

- 不支持任意主题自由绘画。
- 不支持全身人物、复杂手势或复杂人体姿态。
- 不支持复刻特定版权动漫角色。
- 不把 AI 生图作为最终画布主路径。
- MVP 不做登录系统。
- MVP 不做多语言语音控制。
- MVP 不训练专用模型。

## 5. 核心原则

### 5.1 三可验证原则

为了和 AI 生图工具拉开差异，最终作品必须满足“三可验证”：

| 原则 | 含义 | 价值 |
| --- | --- | --- |
| 可回放 | 可从空白画布按操作历史快速重演主要绘画步骤 | 证明不是一次性图片生成 |
| 可分层 | 草图、线稿、基础色、水彩、细节、背景等分层管理 | 证明是绘图工程 |
| 可编辑 | 头发、眼睛、表情、服饰、背景等对象可被局部修改 | 证明支持真实绘图控制 |

### 5.2 数位绘画流程

系统模拟数位板绘画流程，而不是聊天窗口或头像捏脸器：

1. 草图阶段：确定头像结构、脸型、发型轮廓和五官位置。
2. 线稿阶段：绘制清晰线条、发束、眼睛、衣领和配饰。
3. 铺色阶段：填充肤色、发色、眼睛、服装基础色。
4. 水彩阶段：叠加半透明色块、柔边晕染、纸张纹理。
5. 细节阶段：添加高光、脸红、发丝、眼睛亮点、背景装饰。

## 9. 核心交互流程

### 9.1 首次使用

1. 用户点击“开始创作”。
2. 浏览器请求麦克风权限。
3. 系统进入聆听状态。
4. 后续核心操作通过语音完成。

### 9.2 创建作品

1. 用户说：“画一个蓝色长发的二次元女生半身头像，水彩素描风。”
2. ASR 转写语音。
3. 绘图指令解析模型生成结构化绘图计划。
4. 系统用语音和字幕复述：“我会绘制蓝色长发、女生半身头像、水彩素描风格，是否确认？”
5. 用户说：“确认。”
6. 系统自动进入完整绘画流程：草图、线稿、铺色、水彩、细节。

### 9.3 连续修改

1. 用户说：“把眼睛改成紫色。”
2. 系统复述：“我会把眼睛改成紫色，是否确认？”
3. 用户确认。
4. 系统只修改眼睛相关对象，保留角色、风格、背景和其他部件。

### 9.4 暂停与继续

- 用户说：“暂停。”
- 系统停止后续绘制并保留当前状态。
- 用户说：“继续。”
- 系统从暂停阶段继续执行。

### 9.5 语义不明确时

当用户说“这个颜色怪怪的，调一下”这类多义指令时，系统不猜测目标对象，而是温柔追问：

> “你想调整头发、眼睛、衣服，还是背景？”

## 10. 语音交互策略

### 10.1 语言范围

MVP 仅支持中文语音，后续再扩展英文或多语言。

### 10.2 AI 回复风格

回复风格要求：

- 简短。
- 温柔。
- 像绘画助手。
- 不像客服。

示例：

- “好的，我先画草图。”
- “我理解为蓝色长发、女生半身头像，确认开始吗？”
- “已经暂停，继续时说‘继续绘画’。”
- “这个修改会重画头发线稿，确认吗？”

### 10.3 确认策略

- 默认先复述确认，再执行。
- 高风险操作需要二次确认，例如整体重画或清空画布。
- 语义不明确时先追问。
- 识别异常时提示用户换一种说法。

### 10.4 控制词策略

系统不强制用户使用固定口令，而是按语义理解。

实现上采用两层策略：

- 高频控制词本地优先识别，例如确认、取消、暂停、继续、撤销、重做。
- 其他自然语言交给 AI 理解。

## 12. 技术架构

### 12.1 总体架构

```text
用户语音
  ↓
前端麦克风采集
  ↓
千问/DashScope ASR
  ↓
后端 /api/interpret
  ↓
OpenAI-compatible 绘图指令解析接口
  ↓
JSON Schema 校验
  ↓
AI 复述 + 千问/DashScope TTS
  ↓
用户确认
  ↓
前端绘图引擎执行 operations
  ↓
工程数据与操作历史保存
```

### 12.2 API 选型

- ASR/TTS：千问或 DashScope 官方语音能力。
- 绘图指令解析：MVP 先接入 sub2api 中转站提供的 OpenAI-compatible 接口。
- 解析层通过统一 Parser Adapter 封装，后续可切换到千问官方大模型或其他兼容服务。

### 12.3 后端职责

- 管理 ASR/TTS 调用。
- 管理绘图指令解析调用。
- 隐藏 API Key。
- 校验 LLM 输出 JSON。
- 维护会话状态。
- 保存作品工程和操作历史。
- 做缓存、限流和上下文压缩。

### 12.4 前端职责

- 麦克风采集。
- 字幕显示。
- 语音播放。
- 画布渲染。
- 绘图操作执行。
- 图层状态展示。
- 暂停、继续、撤销、重做。
- 轻量回放。

## 15. 成本控制策略

### 15.1 计划采用

- 简单控制指令本地解析，不调用大模型。
- 复杂绘图指令才调用 LLM。
- 绘图渲染在前端本地完成，不使用云端生图作为主路径。
- 作品保存为 JSON 工程文件，降低存储成本。
- 对话上下文只传摘要和当前画布状态，不传完整历史。
- ASR/TTS 按需开启，暂停时不持续调用。
- 缓存常见组件、模板和风格配置。
- 使用 Parser Adapter，方便替换成本更低或更稳定的模型。

### 15.2 后续可采用

- 对常见语音命令做本地意图分类。
- 对相同操作请求做结果缓存。
- 对长会话做状态摘要压缩。
- 对匿名项目设置自动过期清理。
- 登录用户按需保存长期工程，匿名用户保存短期工程。

## 16. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 语音识别错误 | 误执行绘图操作 | 复述确认、追问澄清、撤销重做 |
| LLM 输出不稳定 | 绘图操作无法执行 | JSON Schema 校验、失败重试、字段兜底 |
| 头像效果不够好 | demo 观感不足 | 聚焦单主题、打磨组件库、增加水彩/素描效果 |
| 中转站不稳定 | 解析失败或延迟高 | Parser Adapter 封装，后续切换官方模型 |
| 被误认为生图工具 | 题目契合度下降 | 展示图层、对象、局部编辑和轻量回放 |
| 手部动作难画 | 画面翻车 | MVP 不支持手部，后续做模板化手势 |

## 17. Demo 脚本草案

1. 打开网页，点击“开始创作”授权麦克风。
